Camada de Persistência

Utilizamos o Supabase (PostgreSQL) como motor central. Ele armazena dados relacionais da empresa, histórico de chat e vetores semânticos (pgvector) para o sistema de RAG (Retrieval-Augmented Generation).

SQL_SCHEMA_EXPLORER

PG_VECTOR_STORAGE

-- Extensão ativada para busca semântica
CREATE EXTENSION IF NOT EXISTS vector;

-- Tabela de fragmentos com embeddings
CREATE TABLE document_embeddings (
  id BIGINT PRIMARY KEY,
  content TEXT,
  embedding VECTOR(1536)
);

Por que 1536 dimensões?

Este valor é configurado para ser compatível nativamente com o modelo text-embedding-3-small da OpenAI, garantindo que o n8n possa realizar buscas vetoriais rápidas no Supabase com mínima latência.

Motor de Orquestração n8n

O n8n atua como o sistema nervoso central. O fluxo é modular: um Supervisor analisa a intenção e despacha dinamicamente para o sub-workflow do setor correto, evitando fluxos gigantes e impossíveis de manter.

Ciclo de Execução

  • 01

    Webhook Trigger

    Entrada de dados via Frontend/API.

  • 02

    Análise Cognitiva (Supervisor)

    LLM identifica o setor competente (GPT-4o).

  • 03

    Dispatch Dinâmico

    Execução do sub-workflow via ID do Banco.
